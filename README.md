## Контрольные точки

| Версия | Тег | Точный SHA | Изменения / документы | Демо и проверки | Статус |
|---|---|---|---|---|---|
| КТ-1, 1.0 | cp1 | См. `cp1-submission.json` рядом с папкой `project`; проверка: `git rev-parse cp1^{commit}` | Первичный пакет; все документы перечислены выше | Разбор USM и карточек по `docs/defense/cp1.md`; отчёт комплектности в `docs/quality/cp1-checklist.md`. CI/CD и приложение: не реализованы | Подготовлено; преподавателем не принято |

Сам SHA нельзя буквально вписать в тот же коммит, хеш которого он должен содержать: это изменит коммит. Поэтому неизменяемый тег и команда находятся здесь, а вычисленный полный SHA - во внешнем паспорте сдачи. В архив включён Git bundle с тем же тегом и коммитом. Новая версия сдачи получает cp1-r2, существующий тег не передвигается.

## Как открыть пакет

Документы написаны в Markdown и открываются любым Markdown-редактором. Для чтения кода игры ничего запускать не нужно: реализации на КТ-1 ещё нет. Общий PDF находится рядом с папкой `project` и является удобным экспортом; исходные требования - в Markdown.

Чтобы восстановить локальный репозиторий из архива, выполните из его корня:

```text
git clone project-cp1.bundle orcs-coursework
git -C orcs-coursework rev-parse cp1^{commit}
```

Удалённый репозиторий пока не предоставлен. Перед сдачей нужно опубликовать этот локальный репозиторий на выбранной площадке, отправить преподавателю доступ и указать ссылку/тег/SHA. Публикация и сдача преподавателю в рамках подготовки пакета не выполнялись.

## Границы MVP

Обязательны два серверных бизнес-сценария: сбор комнаты и старт; полная партия с автоматическими правилами и сохранённым итогом. Hot seat, боты и исключение/замена отключившегося участника относятся к следующему релизу. Возврат после короткого обрыва входит в MVP; при безвозвратном уходе сервис ждёт игрока. Полный художественный UI не является критерием реализации сервиса.
