# ADR-001. Модульный монолит и единое ядро

Версия: cp2-docs-draft, 24.11.2026. Статус: проект решения.

Связи: US-001–011; NFR-003/004/006/008. Статус: предложено, серверная реализация не начата.

## Контекст

Нужны hot seat сейчас и удалённые партии позже. Проект делает один человек; дублирование правил на клиенте и сервере усложнит проверку.

## Альтернативы

Полностью клиентская игра: проще, но нет доверенного владельца сетевого состояния. Микросервисы комнат/ходов/очков: возможны, но добавляют распределённые транзакции и поставку без пользы для текущего масштаба.

## Решение

Модульный сервер на C# / ASP.NET Core 10. Core с правилами остаётся независимой библиотекой. Локально им управляет LocalMatchSession; в будущей сети — MatchService. Клиент отправляет намерение, а сервер определяет игрока по токену и выполняет правила. Unity не подключается к БД.

## Последствия

Один процесс и одна транзакция упрощают ход. Сбой API временно останавливает все сетевые партии. Core не знает HTTP, SQL и Unity; сборки контролируют направление зависимостей. Сетевой фасад пока существует только в документах.

## Когда пересматривать

Пересмотреть при подтверждённой нехватке ресурсов на NFR-001 или появлении отдельных команд разработки. Разделять сервисы только после измерений.
