# Контракт HTTP API

Версия: cp2-docs-draft, 24.11.2026. Статус: проект решения.


Машиночитаемый проект: [OpenAPI 3.0.3](../../api/openapi.json); [примеры](../../api/examples.http). Это описание будущего API, не работающий адрес. Файл .http заполняется данными из фактических ответов; ID карты 0 и версия 0 не гарантируют допустимый ход.

## Операции

| Метод и путь | Доступ | Результат |
| --- | --- | --- |
| POST /v1/rooms | X-Request-Key, имя | 201: комната, место, личный токен |
| POST /v1/rooms/join | X-Request-Key, код, имя | 201: участник и состав |
| GET /v1/rooms/{roomId} | Участник этой комнаты | 200: состав, hostMemberId, версия |
| POST /v1/rooms/{roomId}/start | Только создатель | 201: поле с version=0; раздача выполнена один раз |
| GET /v1/matches/{matchId} | Участник этой партии | 200: актуальное поле или сохранённый итог |
| POST /v1/matches/{matchId}/moves | Активный участник | 200: поле после хода и следующего добора |
| GET /health, GET /ready | Техническая проверка | 200: процесс / БД готовы; иначе 503 |

## Поля и версия

Каждое изменение: commandId UUID. Для start/move: expectedVersion; карта: cardId 0–123, territoryId 0–4, side 0/1/2. side=0 только для супероружия; side=1 для обычного орка или первой стороны близнецов; side=2 только для близнецов. Пропуск хода и изменение уже выложенной карты не имеют endpoints.

Идентификатор игрока не приходит в команде: API получает участника из токена и преобразует его seat в Core PlayerId. Версии комнаты и партии независимы. Неизвестные поля отклоняются. Имя после trim должно содержать 1–24 символа; ограничения длины сверяются с Core. JSON UTF-8, тело ≤16384 байт; тип карты определяется серверным каталогом.

Ответ MatchView содержит version, activePlayerSeat, количество колоды и сброса, всех игроков с открытыми руками, пять территорий и победителей. У завершённой партии activePlayerSeat=null. Во внутреннем Core это -1; DTO явно преобразует значение. Маски признаков: 1 Точилы, 2 Швырялы, 4 Рубилы, 8 Крушилы, 16 АААААА. combinationCounts — пять эффективных количеств; выключенный признак даёт 0, а disabledMask позволяет показать «выкл.».

## Доступ и первый ответ

Комната по коду не даёт доступа к чужой начатой партии. Вход разрешён только в lobby. Сервер выдаёт 256-битный токен, хранит hash, отправляет его только в ответе регистрации по HTTPS. Токен — секрет, CommandId сам по себе им не является.

Для create/join клиент заранее создаёт X-Request-Key (32 случайных байта CSPRNG в base64url без padding). Сервер сохраняет hash ключа и зашифрованную квитанцию. При потере самого первого ответа повтор с тем же ключом и commandId возвращает тот же личный токен, не создаёт второе место. Без этого ключа знание commandId не позволяет получить токен. Ключ, токен и Authorization исключаются из логов. Это дополнительный контракт будущего клиента, ещё не реализованный в Unity.

## Повтор и ошибки

Успешный ответ только после COMMIT. Для той же пары scope+commandId сравнивается hash нормализованного тела. Совпало — тот же сохранённый статус/тело и Idempotency-Replayed:true; не совпало — 409 IdempotencyConflict. Проверка квитанции предшествует проверке expectedVersion. Повторяется также аутентификация: чужой токен не получает старый ответ.

| HTTP | Коды и реакция |
| --- | --- |
| 400 | InvalidRequest: неверный JSON/схема. Исправить запрос. |
| 401 | Unauthorized: токен отсутствует или не признан. Не повторять автоматически. |
| 403 | Forbidden: запуск не создателем. |
| 404 | RoomNotFound, MatchNotFound; для чужого ресурса тот же ответ без его данных. |
| 409 | StaleVersion, IdempotencyConflict, RoomFull, MatchAlreadyStarted, NotEnoughPlayers, MatchFinished, WrongPlayer, CardNotInHand, TerritoryClosed, TerritoryFull. Ошибка не меняет состояние. |
| 413 | RequestTooLarge: более 16 КиБ. |
| 422 | InvalidName, InvalidSide, InvalidCommand. |
| 429 | RateLimited + Retry-After. 11-й неверный вход за 60 с с одного адреса блокируется. |
| 503 | Unavailable + Retry-After. При неизвестном исходе повторить исходный commandId. |

InvalidTerritory при значении вне 0–4 отклоняется схемой как 400. Для устаревшей версии возвращается currentVersion, но не состояние чужой партии. Пример ошибки: {"code":"StaleVersion","message":"Обновите поле","requestId":"66666666-6666-4666-8666-666666666666","currentVersion":18}.

Каждый ответ имеет X-Request-Id, связанный с безопасным логом. Истечение токена, отсутствие ресурса и предметная ошибка не запускают бесконечный retry. После потери ответа клиент хранит ID команды; после успешного повтора делает GET, потому что квитанция может относиться к старой версии поля. Новое поле нельзя заменять старым ответом.

Изменение совместимого контракта дополняет /v1; несовместимое требует /v2 или явной миграции. Источник формата: [OpenAPI 3.0.3](https://spec.openapis.org/oas/v3.0.3.html). Сейчас проверены JSON-структура и внутренние ссылки; интеграционное соответствие серверу и полноценный валидатор OpenAPI ещё не запускались.
